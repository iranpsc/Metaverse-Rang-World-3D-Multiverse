# ۰۳ — راهنمای مالک (v3.5.0)

راهنمای گام‌به‌گام از باز کردن بازی تا فرستادن لینک برای بازیکن.

---

## مرحلهٔ ۱ — ساخت فایل محیط (پنل چپ)

پنل چپ (`MetaRange_CreateEnvCanvas ▸ MetaRange_LeftCreatePanel`) مسئول ساخت **فایل JSON محیط** روی سرور است.

| المان | کار |
|-------|-----|
| `EnvNameInput` | نام محیط؛ **خالی بگذارید** تا خودکار شود: `env_20260101_183045` |
| `CreateEnvButton` | «ساخت فایل محیط» |
| `CreateEnvResult` | پیام نتیجه |

| پیام | معنی |
|------|------|
| سبز — «محیط «X» ساخته شد» | محیط جدید ساخته شد |
| زرد — «محیط از قبل وجود دارد» | محیط موجود بود؛ همان استفاده می‌شود |
| قرمز — «خطا: …» | خطای سرور یا نام نامعتبر |

> نام محیط فقط می‌تواند شامل حروف (لاتین/فارسی)، ارقام، `-` و `_` باشد و حداکثر ۶۴ کاراکتر است.

---

## مرحلهٔ ۲ — فعال‌سازی پنل مالک (پنل راست)

تیک **«مالک هستم»** (`OwnerToggle`) را بزنید. با فعال شدن:

| اتفاق | جزئیات |
|-------|--------|
| موقعیت زنده ظاهر می‌شود | هر فریم: نام آواتار، `X/Y/Z` با دو رقم اعشار، چرخش |
| دکمهٔ «ثبت موقعیت» ظاهر می‌شود | — |
| لیست موقعیت‌ها ظاهر می‌شود | `GET /api/list-positions` و ساخت کارت‌ها |
| آواتار پیدا می‌شود | با تگ `Player`، سپس نام‌های رایج (`MetaRangeAvatar`, `Avatar`, `LocalPlayer`, `XR Origin`, `XR Rig`) |

با **برداشتن** تیک، پنل مالک و سکشن لینک بسته می‌شود.

## مرحلهٔ ۳ — ثبت موقعیت

| گام | کار |
|-----|-----|
| ۱ | بازیکن (آواتار) را به نقطهٔ دلخواه ببرید |
| ۲ | در `PositionNameInput` نام یونیک بنویسید، مثلاً `ورودی_اصلی` (خالی = خودکار `pos_xxxxxx`) |
| ۳ | «ثبت موقعیت» را بزنید |

قواعد نام:

| قاعده | نتیجه |
|-------|-------|
| حروف فارسی و لاتین، ارقام، `_`، `-` | مجاز |
| فاصله | تبدیل به `_` |
| کاراکتر دیگر | حذف |
| بیش از ۴۰ کاراکتر | کوتاه می‌شود |
| نام تکراری در همان محیط | پیام «نام تکراری است — یک نام دیگر انتخاب کنید» و **بدون ارسال** |
| محیط ساخته نشده | پیام «اول از پنل چپ «ساخت فایل محیط» را بزنید» و **بدون ارسال** |

بعد از موفقیت، لاگ سرور نشان می‌دهد:

```
POST /api/add-position -> 201  body: env=demo_hall id=ورودی_اصلی pos=(12.5,0,-8.3)
```

> اگر سرور پاسخ `404 Environment not found` بدهد (مثلاً بعد از ری‌استارت و پاک شدن داده‌ها)، سیستم **یک‌بار** محیط را دوباره می‌سازد و ثبت را تکرار می‌کند.

## مرحلهٔ ۴ — لینک، QR و خروجی‌ها (v3.5.0)

سکشن **«لینک و QR»** بلافاصله پس از ثبت موفق باز می‌شود.

لینک تولیدشده:

```
https://metarange.adfam.com/play?env=demo_hall&spawn=ورودی_اصلی
```

| المان | توضیح |
|-------|-------|
| `LinkText` | متن کامل لینک (برای کپی دستی اگر کلیپ‌بورد مسدود بود) |
| `QrRawImage` | تصویر QR کد لینک |
| `LinkStatusText` | پیام وضعیت عملیات خروجی |

### سه دکمهٔ خروجی

| دکمه | نتیجه | پیام وضعیت |
|------|--------|-------------|
| **کپی لینک** | لینک در کلیپ‌بورد سیستم | «لینک کپی شد» (سبز) |
| **دانلود لینک** | فایل متنی تک‌خطی | «فایل لینک ذخیره شد» (سبز) |
| **دانلود QR** | تصویر PNG کد QR | لاگ مسیر فایل در کنسول |

### کپی لینک

| محیط اجرا | رفتار |
|-----------|-------|
| ادیتور / Standalone / Windows / macOS / Linux | کلیپ‌بورد سیستم پر می‌شود ⇒ پیام «لینک کپی شد» |
| WebGL یا مرورگری که کلیپ‌بورد را مسدود کند | پیام «کپی خودکار ممکن نشد — لینک را دستی انتخاب کنید» + `LogWarning` (بدون کرش) |

در حالت مسدود، لینک را از متن `LinkText` دستی انتخاب کنید یا «دانلود لینک» را بزنید.

### دانلود لینک (فایل txt)

| مورد | مقدار |
|------|-------|
| نام فایل | `spawn_{env}_{positionId}.txt` — هر دو بخش با `SanitizePositionName` پاک‌سازی می‌شوند |
| مثال | `spawn_demo_hall_ورودی_اصلی.txt` |
| محتوا | فقط لینک، در **یک خط**، بدون newline |
| کدگذاری | UTF-8 **بدون BOM** (در Notepad و مرورگر درست باز می‌شود) |
| ادیتور (Play Mode) | پنجرهٔ انتخاب مسیر؛ لغو ⇒ «ذخیره لغو شد» |
| Build (بازیکن) | مسیر خودکار در `Application.persistentDataPath` و لاگ مسیر در کنسول |
| خطای نوشتن | پیام «خطا در ذخیره فایل» + `LogError` (بدون کرش) |

### دانلود QR

| محیط اجرا | رفتار |
|-----------|-------|
| ادیتور | `SaveFilePanel` با نام پیشنهادی `qr_spawn` و پسوند `png` |
| Build | `Application.persistentDataPath/qr_spawn.png` |

اگر QR هنوز بارگذاری نشده باشد: «QR هنوز دانلود نشده است» (فقط لاگ).

### وضعیت فعال/غیرفعال دکمه‌ها

تا وقتی لینکی ساخته نشده باشد، «کپی لینک» و «دانلود لینک» **غیرفعال** (خاکستری) هستند. با ثبت موفق موقعیت فعال می‌شوند. اگر به هر دلیل بدون لینک فراخوانی شوند، پیام «ابتدا یک موقعیت ثبت کنید» نشان داده می‌شود.

## مرحلهٔ ۵ — ویرایش زندهٔ موقعیت

هر کارت در `Section_PositionList` دکمهٔ **«ویرایش»** دارد.

| گام | اتفاق |
|-----|--------|
| ۱ | «ویرایش» را بزنید: کارت آبی می‌شود، نام فعلی در فیلد «نام» می‌آید و مقادیر X/Y/Z **و چرخش Rx/Ry/Rz (درجه)** از وضعیت فعلی آواتار پر می‌شود |
| ۲ | **آواتار را حرکت دهید** ⇒ مختصات و **چرخش** هر فریم به‌روز می‌شوند (پیش‌نمایش زنده، **بدون شبکه**) |
| ۳ | اگر می‌خواهید عددی را دستی بنویسید، داخل فیلد کلیک کنید: تا وقتی فیلد focus دارد دست‌نخورده می‌ماند |
| ۴ | نام را می‌توانید تغییر دهید (rename) |
| ۵ | **«تأیید»** = تنها محل ذخیره‌سازی |
| ۶ | **«انصراف»** = بدون هیچ ذخیره‌سازی |

### تفاوت‌های کلیدی رفتار ویرایش

| موضوع | رفتار واقعی |
|-------|-------------|
| «ویرایش» | هیچ درخواست شبکه‌ای نمی‌فرستد |
| در حال ویرایش | فقط **همان یک کارت** هر فریم از بازیکن مقدار می‌گیرد؛ ویرایش کارت بعدی، کارت قبلی را می‌بندد |
| تایپ در فیلد | فیلد focus‌دار بازنویسی نمی‌شود |
| ذخیره | فقط با «تأیید»: اول `PUT /api/rename-position` (اگر نام عوض شده)، بعد `PUT /api/update-position` |
| نام تکراری در rename | پیام «نام تکراری است» و کارت **در حالت ویرایش می‌ماند** |
| انتقال آواتار | با «تأیید» و `moveAvatarOnConfirm = true` آواتار دقیقاً به نقطهٔ ذخیره‌شده منتقل می‌شود (مقاوم در برابر `CharacterController`/`Rigidbody`) |
| چرخش (v3.6) | در ویرایش قابل تغییر است: `Rx/Ry/Rz` بر حسب **درجه** (`eulerAngles`) زنده از آواتار می‌آیند و با «تأیید» به‌صورت `rotation{x,y,z,w}` ذخیره می‌شوند |

پیام‌های وضعیت ویرایش در `RegisterStatusText` (زیر دکمهٔ ثبت) نمایش داده می‌شود:
«ویرایش: فیلدها زنده از موقعیت بازیکن — ذخیره فقط با «تأیید»» · «ویرایش ذخیره شد: X» · «خطا در ویرایش».

### جداکنندهٔ اعشار

مقادیر مختصات با `ParseFloat` خوانده می‌شوند و همهٔ این نگارش‌ها پذیرفته است:

`1.5` · `1,5` · `1٫5` (ممیز عربی) · `12,50` · `-37.9` · نیم‌فاصله

خروجی همیشه با دو رقم اعشار و ارقام لاتین نوشته می‌شود تا در متن RTL به‌هم نریزد.

## مرحلهٔ ۶ — ارسال برای بازیکن

| روش | مناسب برای |
|------|-----------|
| **کپی لینک** | ارسال در چت/پیام‌رسان |
| **دانلود لینک** | آرشیو یا ارسال به‌صورت فایل |
| **دانلود QR** | چاپ روی برگهٔ راهنما، تابلو یا رول |
| متن `LinkText` | کپی دستی در صورت مسدود بودن کلیپ‌بورد |

بازیکن لینک را باز می‌کند، بازی بالا می‌آید و `SpawnFromURL` او را در همان مختصات اسپان می‌کند. جزئیات در [۰۴ — لینک بازیکن و اسپان](04_لینک_بازیکن_و_اسپان.md).

## مرحلهٔ ۷ — تغییر یا پاک کردن موقعیت

| کار | روش |
|-----|-----|
| تغییر نام | کارت → «ویرایش» → فیلد «نام» → «تأیید» |
| تغییر مختصات | کارت → «ویرایش» → آواتار را جابه‌جا کنید → «تأیید» |
| انصراف از تغییر | کارت → «انصراف» (هیچ چیز ذخیره نمی‌شود) |
| پاک کردن کامل یک موقعیت | API ندارد؛ کلید را از فایل `data/environments/<env>.json` حذف کنید و لیست را با برداشتن/گذاشتن تیک «مالک هستم» تازه کنید |
| پاک کردن همهٔ داده‌ها | پوشهٔ `metaverse-spawn-server/data/environments/*.json` را پاک کنید |
