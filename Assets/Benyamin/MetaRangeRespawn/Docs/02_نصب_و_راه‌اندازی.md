# ۰۲ — نصب و راه‌اندازی (v3.5.0)

## پیش‌نیازها

| مورد | نسخه / توضیح |
|------|---------------|
| Unity | 6 (پروژهٔ مرجع با 6.x تست شده) |
| TextMeshPro | همراه Unity |
| `com.nosuchstudio.rtltmpro` | پکیج پشتیبانی فارسی/RTL — فقط **استفاده** می‌شود، تغییری در آن داده نمی‌شود |
| فونت TMP فارسی | Vazir یا Lalezar (هر فونت دارای گلیف فارسی) |

## گام ۱ — سرور

```bash
cd metaverse-spawn-server
npm install        # express، cors، qrcode
node index.js
```

خروجی موفق:

```
──────────────────────────────────────────────
 متارنج v3.1 — سرور ریسپان آواتار
 listening : http://localhost:3000  (http://127.0.0.1:3000)  dual-stack
 data dir  : ...\metaverse-spawn-server\data\environments
 log file  : ...\metaverse-spawn-server\logs\server.log
──────────────────────────────────────────────
```

بررسی سلامت:

```bash
# Windows PowerShell
Invoke-RestMethod http://localhost:3000/api/health
# {"ok":true,"service":"metarange-respawn","version":"3.1","environments":0}
```

| متغیر محیطی | پیش‌فرض | کاربرد |
|-------------|---------|--------|
| `PORT` | `3000` | پورت سرور |
| `HOST` | تنظیم‌نشده ⇒ `::` (dual-stack) | اگر ست شود، فقط روی همان IP گوش می‌دهد |

> داده‌ها در `data/environments/<env>.json` و لاگ در `logs/server.log` ذخیره می‌شود. پاک کردن پوشهٔ `data/environments` همهٔ محیط‌ها را حذف می‌کند (بعداً `OwnerPanel` خودش محیط را دوباره می‌سازد).

## گام ۲ — فونت فارسی

1. فونت فارسی (Vazir / Lalezar) را در پروژه ایمپورت کنید (کاراکترهای `.ttf`).
2. در **TMP Importer** گزینهٔ `Atlas Population Mode = Dynamic` را انتخاب کنید تا گلیف‌های فارسی تولید شوند.
3. فونت TMP حاصل باید در `TMP Essential Resources` موجود باشد (اگر نیست: `Window ▸ TextMeshPro ▸ Import TMP Essential Resources`).

---

## گام ۳ — اجرای Tool

1. صحنه‌ای که آواتار در آن است را باز کنید.
2. **آبجکت Player را انتخاب کنید** (اگر انتخاب نکنید، Tool تگ `Player` را جست‌وجو می‌کند و سپس نام‌های رایج).
3. منو:

   ```
   Tools ▸ متارنج ▸ راه‌اندازی سیستم ریسپان آواتار
   ```

4. Tool این کارها را انجام می‌دهد:

| گام | نتیجه |
|-----|-------|
| `EnsureFolders()` | ساخت پوشه‌های لازم پکیج |
| `ResolveAvatar()` | پیدا کردن Player و **افزودن تگ `Player`** در صورت نبود |
| `EnsureCreateCanvas()` | `MetaRange_CreateEnvCanvas` + Raycaster |
| پنل چپ | `MetaRange_LeftCreatePanel` + `EnvironmentCreator` |
| `EnsureCanvas()` / `EnsureEventSystem()` | Canvas اصلی + EventSystem |
| پنل راست | `MetaRangeRootPanel` + سه سکشن + `OwnerPanel` |
| `EnsureCardPrefab()` | `Prefabs/PositionCard.prefab` |
| `MetaRange_SpawnSystem` | افزودن `SpawnFromURL` |
| `Bind…` | اتصال همهٔ رفرنس‌ها + `LogNulls` گزارش فیلدهای نال |
| پایان | انتخاب و `Ping` پنل، علامت‌گذاری صحنه به‌عنوان Dirty |

> Tool هر بار پنل قبلی را پاک و از نو می‌سازد (idempotent). اگر آواتار پیدا نشود، **هیچ تغییری در صحنه داده نمی‌شود**.

## گام ۴ — تنظیمات Inspector

| کامپوننت | فیلد | پیش‌فرض | توضیح |
|-----------|------|---------|--------|
| `OwnerPanel` | `serverUrl` | `http://localhost:3000` | آدرس سرور |


## ساخت WebGL (اختیاری)

1. لینک بازیکن باید دقیقاً همان مسیری باشد که Build در آن قرار می‌گیرد (`playBaseUrl`).
2. در WebGL، `SpawnFromURL` آدرس را از `Application.absoluteURL` می‌خواند؛ پارامترهای `env` و `spawn` را مرورگر خودش encode می‌کند.
3. کلیپ‌بورد WebGL ممکن است توسط مرورگر مسدود شود؛ در آن حالت پیام «کپی خودکار ممکن نشد — لینک را دستی انتخاب کنید» نمایش داده می‌شود و کاربر می‌تواند لینک را از روی متن `LinkText` کپی کند یا «دانلود لینک» بزند.
4. CORS سرور باز است (`Access-Control-Allow-Origin: *`)، پس درخواست از WebGL بدون تنظیم اضافی کار می‌کند.
