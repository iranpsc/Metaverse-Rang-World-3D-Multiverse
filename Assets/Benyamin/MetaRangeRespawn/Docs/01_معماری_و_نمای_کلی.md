## جریان ۱ — ثبت موقعیت (مالک)

```
1. پنل چپ: «ساخت فایل محیط»
        POST /api/create-env  { environmentName }
        201 ⇒ ساخته شد   |   409 ⇒ از قبل بود (هر دو موفق)
        ⇒ StoredEnvironmentName = نام محیط

2. پنل راست: تیک «مالک هستم»
        ⇒ RefreshList() → GET /api/list-positions?env=…
        ⇒ موقعیت زنده هر فریم از avatar.position نمایش داده می‌شود

3. «ثبت موقعیت»
        محیط خالی است؟  ⇒ پیام «اول از پنل چپ «ساخت فایل محیط» را بزنید» و پایان (بدون شبکه)
        نام = SanitizePositionName(ورودی)  یا  خالی ⇒ "pos_" + ۶ رقم هگز تصادفی
        نام تکراری در knownIds؟  ⇒ پیام «نام تکراری است» و پایان
        POST /api/add-position { environmentName, positionId, position{x,y,z}, rotation{x,y,z,w} }

4. پاسخ موفق ⇒ ShowResult()
        currentLink = playBaseUrl + "?env=" + env + "&spawn=" + posId
        Section_Result فعال می‌شود · دکمه‌های کپی/دانلود فعال می‌شوند · بارگذاری QR

5. اگر سرور 404 «Environment not found» داد (ری‌استارت/پاک شدن data)
        ⇒ ClearStoredName() → EnsureEnvironment() → یک‌بار تلاش مجدد add-position
```

## جریان ۲ — ویرایش کارت

```
«ویرایش» (OnEdit)
   ├─ isEditing = true
   ├─ NotifyEditStarted(this)  ⇒ کارت قبلی (اگر در ویرایش بود) بسته می‌شود — فقط یک کارت هم‌زمان
   └─ PullFromAvatar()          ⇒ X/Y/Z از بازیکن پر می‌شود

Update() هر فریم، فقط وقتی isEditing
   └─ PullFromAvatar() → SetField(...)
        ├─ X/Y/Z از avatar.position
        └─ Rx/Ry/Rz از avatar.eulerAngles (درجه) — v3.6
        └─ اگر فیلد isFocused باشد دست‌نخورده می‌ماند (تایپ کاربر پاک نشود)
        └─ در isBusy (هنگام ذخیره) فریز می‌شود

«تأیید» (ConfirmRoutine)  ← تنها محل ذخیره‌سازی
   ۱) اگر نام عوض شده ⇒ PUT /api/rename-position
        409 ⇒ کارت در حالت ویرایش می‌ماند تا کاربر نام دیگری بزند
   ۲) خواندن X/Y/Z با ParseFloat ⇒ PUT /api/update-position
   ۳) خواندن Rx/Ry/Rz با ParseFloat ⇒ Quaternion.Euler (اگر فیلدها نال باشند، چرخش قبلی حفظ می‌شود)
   ۴) moveAvatarOnConfirm=true ⇒ MoveAvatarTo(pos, rot)  ← موقعیت و چرخش
   ۵) NotifyEditEnded + RefreshList

«انصراف» (OnCancel)  ← بدون هیچ ذخیره‌سازی
```

**نکتهٔ کلیدی:** `OnEdit` هیچ درخواست شبکه‌ای نمی‌فرستد. پیش‌نمایش زنده کاملاً محلی است.

## لایهٔ شبکه (`MetarangeNet`)

| نکته | رفتار |
|------|-------|
| متدها | `PostJson` (POST)، `PutJson` (PUT)، `Get` (GET) |
| هدر | `Content-Type: application/json` با بدنهٔ UTF-8 واقعی (نه query) |
| Timeout | ۱۰ ثانیه (GET/POST/PUT) · ۱۲ ثانیه برای QR |
| Fallback مسیر | اگر `localhost` خطای اتصال داد، **یک‌بار** با `127.0.0.1` تلاش می‌شود |
| گزارش خطا | `Reply.Detail()` = `url` + `responseCode` + `error` + `body` |

## سیاست نام‌گذاری (`SanitizePositionName`)

| قاعده | رفتار |
|-------|-------|
| مجاز | حروف لاتین و فارسی، ارقام، `_`، `-` |
| فاصله (space) | تبدیل به `_` |
| سایر کاراکترها | حذف |
| طول | حداکثر ۴۰ کاراکتر |
| خالی | `string.Empty` ⇒ در ثبت، نام خودکار `pos_xxxxxx` ساخته می‌شود |

سرور همان قاعده را با `safeName` و محدودیت ۶۴ کاراکتر اعمال می‌کند (و `path traversal` را می‌بندد).

## زنجیرهٔ QR (fallback)

```
① سرور خودمان:  GET {serverUrl}/api/qr?data=<EscapeURL(link)>          ← پیشنهادی
② اگر ناموفق:   qrPrimaryTemplate  → https://api.qrserver.com/v1/create-qr-code/?size=256x256&data={DATA}
③ اگر ناموفق:   qrFallbackTemplate → https://quickchart.io/qr?size=256&margin=2&text={DATA}
✗ هر سه ناموفق ⇒ LogError + یادآوری اینکه «لینک متنی همچنان معتبر است»
```

`useLocalServerQr` در Inspector قابل خاموش‌کردن است؛ در هر تلاش یک هدر `User-Agent` مرورگر هم فرستاده می‌شود چون بعضی سرویس‌های QR درخواست غیرمرورگری را رد می‌کنند.
