# ۰۸ — عیب‌یابی (v3.5.0)

## ۱) خطاهای سرور

| پیام / کد | علت | راه‌حل |
|------------|-----|---------|
| `404 Environment not found` روی `add-position` | فایل محیط روی سرور نیست (سرور تازه، یا `data/environments` پاک شده) | در حالت عادی `OwnerPanel` خودش یک‌بار محیط را می‌سازد و تلاش مجدد می‌کند. اگر باز هم دیدید: از پنل چپ «ساخت فایل محیط» را بزنید. |
| `404 Environment not found` روی `list-positions` / `get-position` | نام محیط اشتباه یا داده پاک شده | نام را با `data/environments/<env>.json` مقایسه کنید |
| `404 Position not found` | شناسه اشتباه است **یا** موقعیت rename شده | لینک قدیمی بی‌اعتبار شده؛ از پنل، لینک جدید بگیرید |
| `409 Position already exists` (هنگام ثبت) | نام یونیک تکراری است | نام دیگری انتخاب کنید یا فیلد نام را خالی بگذارید تا خودکار ساخته شود |
| `409 Position already exists` (هنگام rename) | نام جدید از قبل وجود دارد | کارت در حالت ویرایش می‌ماند؛ نام دیگری بزنید |
| `400 Missing/invalid fields…` | بدنه JSON ناقص یا مختصات/کوارنیون نامعتبر (مؤلفه‌های `NaN`/`Infinity`) | فقط از پنل استفاده کنید یا بدنه را اصلاح کنید |
| `400 data query is required` | `GET /api/qr` بدون پارامتر `data` | — |
| `400 data too long` | متن QR بیش از ۱۲۰۰ کاراکتر | لینک را کوتاه کنید |
| `400 Invalid JSON body` | JSON خراب ارسال شده | معمولاً مشکل سمت کلاینت است |
| `404 Unknown endpoint: …` | مسیر اشتباه (مثلاً `/api/position`) | مسیرها را با [۰۶ — مرجع API](06_مرجع_API_سرور.md) تطبیق دهید |
| اتصال به سرور برقرار نمی‌شود | سرور اجرا نشده یا پورت اشتباه | `node index.js` و `GET /api/health` را بررسی کنید |

## ۲) مشکلات سرور

| مشکل | علت | راه‌حل |
|------|-----|---------|
| `EADDRINUSE` | پورت ۳۰۰۰ اشغال است | `PORT=3001 node index.js` و همان مقدار را در `serverUrl` پنل‌ها ست کنید |
| لاگ فایل ساخته نمی‌شود | پوشهٔ `logs` قابل نوشتن نیست | سیستم هشدار می‌دهد و در کنسول ادامه می‌دهد؛ دسترسی نوشتن پوشه را اصلاح کنید |
| از بیرون (LAN/اینترنت) وصل نمی‌شود | سرور فقط روی لوپ‌بکاک | `HOST` را تنظیم نکنید (حالت پیش‌فرض dual-stack است) و فایروال پورت را باز کنید |
| IPv4 کار می‌کند ولی WebGL نه | مرورگر `localhost` را به IPv6 می‌برد | سرور dual-stack گوش می‌دهد؛ مطمئن شوید متغیر `HOST` ست نشده است |

## ۳) UI یونیتی

| مشکل | علت | راه‌حل |
|------|-----|---------|
| هیچ پنلی ظاهر نمی‌شود | Tool اجرا نشده | Player را انتخاب کنید و `Tools ▸ متارنج ▸ راه‌اندازی سیستم ریسپان آواتار` |
| لاگ «آواتار پیدا نشد» | نه انتخاب فعالی در Hierarchy، نه تگ `Player` | Player را انتخاب و دوباره Tool را اجرا کنید، یا در Inspector فیلد `avatar` را دستی ست کنید، یا آبجکت را به `Player` تغییر نام دهید |
| متن فارسی به‌هم‌ریخته/برعکس | فونت TMP فارسی تنظیم نشده | فونت Vazir/Lalezar را با `Dynamic Atlas` بسازید و در RTLTMPText بررسی کنید |
| رویداد کلیک کار نمی‌کند | `EventSystem` یا `GraphicRaycaster` ندارد | Tool این‌ها را می‌سازد؛ دوباره اجرا کنید. در Build کنترلر Event System را با Input System همگام کنید |
| دو پنل روی هم می‌افتند | نسخهٔ قدیمی در صحنه مانده | Tool قبل از ساخت، پنل قبلی را با `DestroyAllByName` حذف می‌کند؛ فقط یک‌بار اجرا کنید و صحنه را ذخیره کنید |
| سکشن‌ها روی هم overlap دارند | ارتفاع دستی اشتباه | ارتفاع‌ها با `FinalizeSection` محاسبه می‌شوند؛ Tool را دوباره اجرا کنید |
| «ثبت موقعیت» فقط پیام راهنما می‌دهد | محیط ساخته نشده | پنل چپ ← «ساخت فایل محیط» |
| دکمه‌های کپی/دانلود خاکستری‌اند | هنوز لینکی ساخته نشده | یک موقعیت ثبت کنید تا `ShowResult` آن‌ها را فعال کند |
| پیام «ابتدا یک موقعیت ثبت کنید» | بدون لینک فراخوانی شده | ابتدا ثبت کنید |

## ۴) موقعیت زنده و ویرایش

| مشکل | علت | راه‌حل |
|------|-----|---------|
| «موقعیت زنده» به‌روز نمی‌شود | تیک «مالک هستم» خورده نیست | تیک را بزنید (متن فقط در حالت مالک نمایش داده می‌شود) |
| «آواتار پیدا نشد» داخل متن زنده | آواتار در زمان اجرا عوض شده | خودکار دوباره پیدا می‌شود؛ اگر نشد، تگ `Player` را درست کنید یا `SetAvatar` را صدا بزنید |
| اعداد X/Y/Z در کارت با حرکت آواتار عوض نمی‌شوند | کارت در حالت ویرایش نیست | «ویرایش» را بزنید؛ پیش‌نمایش زنده فقط در حالت ویرایش فعال است |
| تایپ کاربر در فیلد پاک می‌شود | فیلد focus ندارد | روی فیلد کلیک کنید؛ `SetField` فیلد focus‌دار را نمی‌نویسد |
| دو کارت هم‌زمان در حالت ویرایش | نسخهٔ قدیمی کد | `editingCard` استاتیک شده؛ `ClearCards` هم آن را پاک می‌کند. پکیج را به‌روز و Tool را دوباره اجرا کنید |
| با «تأیید» آواتار جابه‌جا نمی‌شود | `moveAvatarOnConfirm` خاموش است، یا `CharacterController` بعداً موقعیت را برمی‌گرداند | گزینه را در prefab کارت روشن کنید؛ `MoveAvatarTo` CC را موقتاً خاموش و RB را صفر می‌کند |
| پیام «نام تکراری است» و کارت بسته نمی‌شود | رفتار درست: کارت در ویرایش می‌ماند | نام دیگری انتخاب کنید و دوباره «تأیید» بزنید |
| مختصات با کاما صفر ذخیره می‌شد | نسخهٔ قدیمی `ParseFloat` | نسخهٔ فعلی `٫`، `،`، کاما و نیم‌فاصله را می‌پذیرد (`1,5` ⇒ `1.50`) |
| «انصراف» هم چیزی ذخیره می‌کند | نباید | در نسخهٔ فعلی `OnCancel` هیچ درخواستی نمی‌فرستد |

## ۵) خروجی لینک (کپی / دانلود txt)

| مشکل | علت | راه‌حل |
|------|-----|---------|
| پیام «کپی خودکار ممکن نشد — لینک را دستی انتخاب کنید» | WebGL یا مرورگر کلیپ‌بورد را مسدود کرده | لینک را از متن `LinkText` دستی کپی کنید یا «دانلود لینک» را بزنید. این رفتار امن است (بدون کرش). |
| کلیپ‌بورد خالی است ولی پیام موفق دیده می‌شود | بعضی محیط‌ها بی‌صدا نوشتن را رد می‌کنند | لینک را در ویرایشگر متن paste و بررسی کنید |
| فایل txt نام عجیب دارد | نام محیط/موقعیت پاک‌سازی شده | قاعده: فقط حروف لاتین/فارسی، ارقام، `_`، `-` و حداکثر ۴۰ کاراکتر — این رفتار عمدی است |
| فایل txt در Build ذخیره نمی‌شود | مسیر `persistentDataPath` ممکن است نانوشتنی باشد | پیام «خطا در ذخیره فایل» + لاگ خطا را ببینید؛ مسیر در `Debug.Log` چاپ می‌شود |
| در ادیتور پنجرهٔ ذخیره باز نمی‌شود | کد خارج از Play Mode است | Tool/کد فقط در Play Mode کار می‌کند |
| متن فارسی فایل txt به‌هم‌ریزیده است | فایل با BOM یا کدگذاری اشتباه باز شده | فایل **UTF-8 بدون BOM** نوشته می‌شود؛ در Notepad یا VS Code درست باز می‌شود |
| «ذخیره لغو شد» | در پنجرهٔ انتخاب مسیر لغو کردید | رفتار عادی است، خطا نیست |
| QR نمایش داده نمی‌شود | هر سه منبع QR ناموفق بوده | کنسول را ببینید؛ لینک متنی معتبر است. سرور محلی (`/api/qr`) را فعال و قابل دسترس کنید. |

## ۶) اسپان بازیکن

| مشکل | علت | راه‌حل |
|------|-----|---------|
| بازیکن در نقطهٔ پیش‌فرض اسپان می‌شود | پارامترهای `env`/`spawn` در URL نیستند | لینک را کامل کپی کنید؛ `playBaseUrl` باید همان مسیر Build باشد |
| لاگ «پارامتر env/spawn در URL یافت نشد» | `Application.absoluteURL` خالی است (ادیتور/بیلد) | در ادیتور/بیلد با `url=…` تست کنید: `MyGame.exe url="http://localhost:3000/?env=demo_hall&spawn=pos_4F7A21"` |
| لاگ «خطا در API — … responseCode=404» | نام محیط/موقعیت اشتباه یا لینک قدیمی | لاگ سرور را ببینید؛ نام‌ها باید با فایل JSON یکی باشند |
| نام فارسی `spawn` خوانده نمی‌شود | پارامتر encode نشده وارد `GetParam` شده | `GetParam` خودش `UnEscapeURL` می‌کند؛ اگر باز هم مشکل بود، مطمئن شوید `EscapeURL` در `FetchSpawn` اعمال شده است |
| اسپان خیلی زود (قبل از آماده شدن آواتار) انجام می‌شود | `Start` خودکار زودتر از ساخته شدن بازیکن است | از `ApplySpawnFromUrl()` بعد از لود صحنه استفاده کنید — [۰۵ — یکپارچه‌سازی](05_یکپارچه‌سازی_با_برنامه_اصلی.md) |
| لینک بازیکن به صفحهٔ اشتباه می‌رود | `playBaseUrl` با مسیر Build فرق دارد | مقدار `playBaseUrl` را در Inspector اصلاح کنید |

## ۷) چند دستور تشخیصی

```powershell
# سلامت سرور
Invoke-RestMethod http://localhost:3000/api/health

# محیط‌های موجود
Get-ChildItem .\metaverse-spawn-server\data\environments\*.json | Select-Object Name

# محتوای یک محیط
Get-Content .\metaverse-spawn-server\data\environments\demo_hall.json -Encoding UTF8

# ۱۰ خط آخر لاگ سرور
Get-Content .\metaverse-spawn-server\logs\server.log -Encoding UTF8 -Tail 10
```

| در کنسول Unity دنبال چه بگردید | معنی |
|----------------------------------|------|
| `[OwnerPanel] ثبت موقعیت: env=… posId=…` | ثبت آغاز شد |
| `[OwnerPanel] لینک کپی شد: …` | کپی موفق |
| `[OwnerPanel] فایل لینک ذخیره شد: …` | مسیر فایل txt |
| `[OwnerPanel] آواتار خودکار وصل شد (…)` | آواتار پیدا و وصل شد |
| `[OwnerPanel] خطای خالی بودن رفرنس‌ها (LogNulls)` | یک Bind انجام نشده؛ Tool را دوباره اجرا کنید |
| `[SpawnFromURL] اسپان در (x, y, z)` | اسپان موفق |
| `[متارنج] اتصال به … ناموفق — تلاش مجدد با 127.0.0.1` | fallback شبکه فعال شد |
