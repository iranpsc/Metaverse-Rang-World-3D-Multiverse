# ۱۰ — جریان کامل: دکمهٔ لابی ⇒ محیط ⇒ لینک

> **تفکیک مسئولیت‌ها**
> - **سرور لوکال MetaRange** = فقط JSON محیط و مختصات اسپان (`env`, `spawn`, `position`, `rotation`).
>   هیچ نقشی در حرکت بازیکن ندارد.
> - **سرور شبکهٔ آنلاین (Network_A / Dedicated)** = مالک حرکت، مالکیت و authority آواتار.
>   هیچ‌چیز از سمت MetaRange جایگزین آن نمی‌شود و آواتار دوم ساخته نمی‌شود.

## ۲) زنجیرهٔ رویداد (بدون تغییر در Network_A)

```
CompletedBuildingRoomListItemView.HandleClick()
   └ clicked?.Invoke(building)
Lobby1RealtimeSceneController.EnterSelectedBuildingAsync(building)
   └ RealtimeRoomGameServerManager.EnterBuildingRoomAsync(building)
        ├ ResolveBuildingRoomAsync  → رومی با roomName == کد ساختمان، وگرنه CreateRoom
        ├ JoinRoomReliableAsync
        └ NotifyRoomJoined → OnRoomJoinedFor3D(roomId)      ← نقطهٔ اتصال متارنج
DedicatedGameServerRealtimeRoomBinderWebGL
   └ OnRoomJoinedFor3D → اتصال Dedicated → LoadSceneAsync("WebGL_Enviroment", Single)
```

**نام دکمه = نام env:** متن دکمه دقیقاً `building.feature_properties_id` است و
همان مقدار `roomName` روم و در نهایت `CurrentRoomName` می‌شود.

## ۳) کاری که متارنج انجام می‌دهد (رویداد → Context → اسپان)

`MetaRangeLobbyEnvironmentBridge.HandleRoomJoined(roomId)`:

| گام | کار | در صورت خطا |
|-----|-----|-------------|
| ۱ | `rawEnv` از `CurrentRoomName` (fallback: `roomId`) | اگر خالی ⇒ `LastError = environment_name_unresolved` و توقف |
| ۲ | `EnvironmentCreator.NormalizeEnvironmentName(rawEnv)` | حذف فاصله/کاراکتر غیرمجاز، بریدن تا ۶۴ |
| ۳ | `EnvironmentCreator.EnsureEnvironment(serverUrl, env, reply)` | `201` یا `409` هر دو موفق؛ `400` ⇒ توقف با لاگ |
| ۴ | `EnvironmentCreator.LockStoredName(env)` ⇒ **Context مشترک** | — |
| ۵ | `GET /api/list-positions?env=` | خالی/۴۰۴ ⇒ فقط Context قفل است، **خطایی داده نمی‌شود** |
| ۶ | انتخاب نقطه: `PerUserStableHash` (هش پایدار `userId`) یا `FirstAvailable` | — |
| ۷ | `GET /api/get-position?env=&spawn=` | در ۴۰۴ از مقدار همان لیست استفاده می‌شود |
| ۸ | `MetaRangeNetworkSpawnBridge.ApplyPoseWhenPlayerReady(...)` | منتظر local player شبکه می‌ماند |

### Context مشترک

```csharp
EnvironmentCreator.StoredEnvironmentName   // static
EnvironmentCreator.LockStoredName(env)     // نرمال‌سازی + قفل
```

`OwnerPanel` همین مقدار را می‌خواند (`L239`, `L337`, `L506`) ⇒
**ثبت موقعیت، لیست کارت‌ها، کپی لینک، QR و دانلود** همگی روی همان env کار می‌کنند
و لینک خروجی به شکل `playBaseUrl?env=<env>&spawn=<id>` ساخته می‌شود.

## ۴) اولویت لینک وقتی کاربر مستقیم وارد می‌شود

بازیکنی که فقط با لینک `?env=&spawn=` می‌آید و از لابی عبور نکرده:
`SpawnFromURL` / `MetaRangeNetworkSpawnBridge` همان مسیر قبلی را ادامه می‌دهند.
اگر بریج لابی هم فعال باشد، `SpawnFromURL` جابه‌جایی آفلاین را انجام **نمی‌دهد**
تا آواتار دوم ساخته نشود.

## ۵) قاعدهٔ نام محیط (سرور Node)

```js
/^[A-Za-z0-9_\-\u0600-\u06FF]+$/    // طول ≤ ۶۴
```

- حروف لاتین، رقم، `-`، `_` و **حروف فارسی/عربی** مجازند.
- **فاصله و نیم‌فاصلهٔ U+200C مجاز نیست** ⇒ نرمال‌ساز در `NormalizeEnvironmentName` حذفشان می‌کند.
- نام تکراری ⇒ `409` که در متارنج **موفقیت** حساب می‌شود (idempotent).

## ۶) چک‌لیست تست دستی

```
1) cd metaverse-spawn-server && node index.js      ⇒ GET /api/health ⇒ {"ok":true,…}
2) Tools ▸ متارنج ▸ بررسی اتصال لابی (Lobby 1 WebGL)  ⇒ همه OK، شامل نام صحنه‌ها
3) Tools ▸ متارنج ▸ راه‌اندازی سیستم ریسپان آواتار
4) Play در صحنهٔ Lobby 1 WebGL  ⇒ کلیک روی دکمهٔ یک محیط
   لاگ انتظار:
   [متارنج لابی] ورود به محیط | env=… | roomId=…
   [EnvironmentCreator] محیط «…» آماده است (ساخته شد | از قبل وجود داشت)
   [متارنج لابی] Context.env قفل شد | … | created|already_exists
   [متارنج لابی] پوز محیط ثبت شد | env=… | spawn=… | points=…
5) ورود به WebGL_Enviroment ⇒ Tools ▸ متارنج ▸ نمایش Context محیط فعلی ⇒ همان env
6) پنل مالک ⇒ ثبت موقعیت ⇒ لینک/QR ⇒ باز کردن لینک ⇒ همان نقطه (best-effort)
```

## ۷) محدودیت‌های صادقانه
